Read src/flights/types.ts to understand the current FlightResult interface structure.

Add the following to the FlightResult interface:
  availabilityType?: 'confirmed' | 'calendar' | 'estimated';

Make it optional (?) because:
1. Existing scrapers don't set it — they inherit 'confirmed' status from the SCRAPER_REGISTRY entry, not the result object.
2. The history-writer checks availabilityType at the scraper level (registry), not the result level.
3. Optional field prevents breaking changes in all existing code that creates FlightResult objects.

Also export a type alias for reuse:
  export type AvailabilityType = 'confirmed' | 'calendar' | 'estimated';

Then update the FlightResult field to use the alias:
  availabilityType?: AvailabilityType;

Do NOT change any other existing fields in FlightResult. Do NOT add default values. Do NOT modify the SearchParams or CabinCode types unless they also need AvailabilityType.

Placement: Add the field near other optional metadata fields (after required flight data fields like milesRequired, departureDate, etc.).
