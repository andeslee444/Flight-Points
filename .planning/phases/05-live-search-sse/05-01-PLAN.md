## Context

The Harbor Express server (`src/flights/web-server.ts`) already has a fully-working SSE endpoint at `/api/flights/live-search` that streams `scraper-started`, `scraper-progress`, `result`, `scraper-done`, `scraper-error`, `scraper-skipped`, and `complete` events. The Next.js frontend on Vercel cannot run Python scrapers, so it must proxy SSE requests to Harbor.

This plan does two things: (1) adds `rewrites()` to `next.config.ts` so the browser's `EventSource` connects to the Vercel URL and gets transparently proxied to Harbor, and (2) creates a Zustand store that holds live search state (results, per-scraper status, elapsed time) consumed by the hook and components in later plans.

**Why rewrites instead of a Route Handler:** Route Handlers on Vercel serverless have a hard timeout (~10s hobby, 60s pro). Scrapes take 20-60s. `rewrites()` is a transparent TCP proxy with no timeout.

**HARBOR_URL must be set in Vercel dashboard** — if missing, the rewrite destination defaults to `http://HARBOR_URL_NOT_SET` (deliberately broken, not `localhost`) so the failure is obvious.

## Must-Haves (Goal-Backward)

1. `next.config.ts` has a `rewrites()` function that proxies `/api/flights/live-search` to `${HARBOR_URL}/api/flights/live-search`
2. `next.config.ts` has a `headers()` function that sets `X-Accel-Buffering: no` on the `/api/flights/live-search` path (anti-buffering for SSE streaming)
3. `HARBOR_URL` env var defaults to `http://HARBOR_URL_NOT_SET` (NOT `localhost`) when missing — makes failures loud
4. `.env.example` documents the `HARBOR_URL` variable
5. `stores/live-search-store.ts` exports `useLiveSearchStore` with: `isLive`, `elapsedSeconds`, `liveResults`, `scrapers` map, and actions: `startLive`, `resetLive`, `addResult`, `updateScraper`, `setElapsed`, `finishLive`
6. `addResult` deduplicates by a composite key (airline + flightNumber + departureDate + cabin) using an in-memory `Set`
7. The store does NOT use `persist` middleware — `Set<string>` is not serializable and live state is ephemeral
8. `next build` succeeds with the updated config

### Modify next.config.ts

The current `next.config.ts` has only the `experimental.extensionAlias` config. Add `rewrites()` and `headers()` async functions.

**Replace the entire contents of `next.config.ts` with:**

```typescript
import type { NextConfig } from 'next';

const config: NextConfig = {
  experimental: {
    // Resolve .js extensions to .ts files.
    // The daemon source files (transfer-partners.ts, sweet-spots.ts, airports.ts, db-drizzle.ts)
    // use NodeNext-style .js extensions in their imports (e.g., import ... from './airports.js').
    // Next.js / Turbopack needs this alias to find the .ts source files.
    extensionAlias: {
      '.js': ['.ts', '.tsx', '.js'],
    },
  },
  async rewrites() {
    const harborUrl = process.env.HARBOR_URL || 'http://HARBOR_URL_NOT_SET';
    return [
      {
        source: '/api/flights/live-search',
        destination: `${harborUrl}/api/flights/live-search`,
      },
    ];
  },
  async headers() {
    return [
      {
        source: '/api/flights/live-search',
        headers: [
          { key: 'X-Accel-Buffering', value: 'no' },
        ],
      },
    ];
  },
};

export default config;
```

**Key details:**
- The `HARBOR_URL` env var must be set in both local `.env` and Vercel dashboard (e.g., `http://150.136.249.186:3000` or `http://harbor.local:3000`)
- The fallback `http://HARBOR_URL_NOT_SET` is intentionally not a valid URL — if a developer forgets to set `HARBOR_URL`, the rewrite fails loudly instead of silently connecting to localhost
- `X-Accel-Buffering: no` tells proxy layers not to buffer SSE responses — events should stream incrementally, not arrive in bursts
- Next.js rewrites automatically pass through all query string parameters (`from`, `to`, `class`, `program`, `date`)

### Create stores/live-search-store.ts

Create a new file. This store holds all state for the live SSE search: connection status, elapsed time, accumulated results, and per-scraper status. It follows the same pattern as the existing `stores/search-store.ts` and `stores/filter-store.ts`.

```typescript
'use client';

import { create } from 'zustand';

// ── Types ──────────────────────────────────────────────────

export type ScraperStatus = 'pending' | 'running' | 'done' | 'error' | 'skipped';

export interface ScraperState {
  key: string;
  name: string;
  status: ScraperStatus;
  message: string;
  resultCount: number;
}

/**
 * Shape of a live result as received from the Harbor SSE endpoint.
 *
 * Harbor's enrichFlightResult() produces a superset of these fields.
 * We store them as-is (not as EnrichedDeal) because the Harbor enrichment
 * does not include all EnrichedDeal fields (missing transferFrom, sweetSpot,
 * region, transferBonuses, scrapedAt). The component layer maps these to
 * EnrichedDeal-compatible objects for rendering via FlightResultCard.
 */
export interface LiveFlightResult {
  airline: string;
  flightNumber: string;
  origin: string;
  destination: string;
  departureDate: string;
  departureTime: string;
  arrivalTime: string;
  duration: string;
  stops: number;
  cabin: string;
  pointsRequired: number;
  pointsProgram: string;
  points: number;
  taxes: number;
  cpp: number | undefined;
  dealRating: 'hot' | 'good' | 'fair' | 'unknown';
  cabinDisplay: string;
  route: string;
  direct: boolean;
  program: string;
  programDisplay: string;
  transferPath: string;
  bookingUrl: string;
  source: string;
  awardType?: string;
  cashPrice?: number;
}

// ── Store ──────────────────────────────────────────────────

interface LiveSearchState {
  // Connection state
  isLive: boolean;
  elapsedSeconds: number;
  // Results accumulation
  liveResults: LiveFlightResult[];
  seenKeys: Set<string>;
  // Per-scraper status
  scrapers: Record<string, ScraperState>;
  // Actions
  startLive: () => void;
  resetLive: () => void;
  addResult: (flight: LiveFlightResult) => void;
  updateScraper: (key: string, patch: Partial<ScraperState>) => void;
  setElapsed: (s: number) => void;
  finishLive: () => void;
}

export const useLiveSearchStore = create<LiveSearchState>()((set) => ({
  isLive: false,
  elapsedSeconds: 0,
  liveResults: [],
  seenKeys: new Set<string>(),
  scrapers: {},

  startLive: () =>
    set({
      isLive: true,
      liveResults: [],
      seenKeys: new Set<string>(),
      scrapers: {},
      elapsedSeconds: 0,
    }),

  resetLive: () =>
    set({
      isLive: false,
      liveResults: [],
      seenKeys: new Set<string>(),
      scrapers: {},
      elapsedSeconds: 0,
    }),

  addResult: (flight) =>
    set((state) => {
      const key = `${flight.airline}-${flight.flightNumber}-${flight.departureDate}-${flight.cabin}`;
      if (state.seenKeys.has(key)) return {};
      const newSeen = new Set(state.seenKeys);
      newSeen.add(key);
      return {
        liveResults: [...state.liveResults, flight],
        seenKeys: newSeen,
      };
    }),

  updateScraper: (key, patch) =>
    set((state) => ({
      scrapers: {
        ...state.scrapers,
        [key]: {
          key,
          name: '',
          status: 'pending' as ScraperStatus,
          message: '',
          resultCount: 0,
          ...state.scrapers[key],
          ...patch,
        },
      },
    })),

  setElapsed: (s) => set({ elapsedSeconds: s }),

  finishLive: () => set({ isLive: false }),
}));
```

**Key design decisions:**
- `LiveFlightResult` instead of `EnrichedDeal`: Harbor's SSE endpoint sends its own enriched format (from `web-server.ts:enrichFlightResult()`), which is a subset of `EnrichedDeal`. Storing the Harbor format directly avoids a lossy mapping. The component layer (Plan 05-03) will map these to `EnrichedDeal`-compatible objects.
- `seenKeys: Set<string>`: Used for O(1) dedup check. The `Set` is fine for runtime use but is not serializable — do NOT add `persist` middleware to this store.
- `addResult` returns `{}` (empty object) when a duplicate is detected — Zustand treats this as a no-op (no re-render).
- `updateScraper` merges `patch` into the existing scraper state with sensible defaults for new scrapers.
