## Context

Plan 05-01 created the `rewrites()` proxy (browser EventSource connects to Vercel URL, transparently forwarded to Harbor) and the `useLiveSearchStore` Zustand store that holds live results, scraper status, and elapsed time.

This plan creates the `useLiveSearch` hook that manages the EventSource lifecycle: opens a connection when search params are available, dispatches SSE events to the Zustand store, runs an elapsed-time timer, and cleans up on unmount or when search params change.

The hook is called from `SearchResults` (already `'use client'`) in Plan 05-03. It does NOT render anything — it only manages the SSE connection and pushes events into the store.

**SSE event types from Harbor** (verified from `src/flights/web-server.ts`):
- `scraper-started`: `{ scraper: string, name: string, status: 'running' }`
- `scraper-progress`: `{ scraper: string, message: string, date?: string }`
- `result`: `{ flight: { ...enrichedFields } }`
- `scraper-done`: `{ scraper: string, name: string, resultCount: number, status: 'done' }`
- `scraper-error`: `{ scraper: string, name: string, error: string, status: 'error' }`
- `scraper-skipped`: `{ scraper: string, name: string, reason: string, status: 'skipped' }`
- `complete`: `{ totalResults, scrapersRun, scrapersSucceeded, scrapersFailed }`
- `search-error`: `{ message: string }` (concurrency limit hit or fatal error)

**CRITICAL:** All Harbor events are **named events** (`event: scraper-started`). They fire ONLY on `addEventListener('name', ...)`, NOT on `es.onmessage`. Never use `onmessage`.

## Must-Haves (Goal-Backward)

1. `useLiveSearch(from, to, cabin, program, date, enabled)` opens an EventSource to `/api/flights/live-search?from=...&to=...&class=...&program=...&date=...`
2. Hook dispatches `scraper-started`, `scraper-progress`, `result`, `scraper-done`, `scraper-error`, `scraper-skipped`, `complete`, and `search-error` events to the Zustand store
3. Hook starts an interval timer that updates `elapsedSeconds` every 1s while the SSE connection is open
4. When search params change (`from`, `to`, `cabin`, `program`, `date`), the old EventSource is closed, the store is reset, and a new connection opens
5. When `enabled` is false or `from`/`to` are empty, no connection opens
6. Cleanup on unmount: EventSource closed, timer cleared, store reset
7. Uses `addEventListener` for all named events (NOT `onmessage`)
8. Uses `es.onerror` as a fallback to detect connection death (calls `finishLive` if `readyState === CLOSED`)

### Create hooks/use-live-search.ts

```typescript
'use client';

import { useEffect, useRef } from 'react';
import { useLiveSearchStore } from '@/stores/live-search-store';
import type { LiveFlightResult } from '@/stores/live-search-store';

/**
 * Hook that manages an EventSource connection to Harbor's live search SSE endpoint.
 *
 * Opens a connection when enabled and search params are present. Dispatches all
 * SSE events to the useLiveSearchStore. Cleans up on unmount or param change.
 *
 * @param from    - Origin airport code(s), e.g. "JFK" or "JFK,EWR,LGA"
 * @param to      - Destination airport code(s)
 * @param cabin   - Cabin class: "economy" | "business" | "first"
 * @param program - Credit card program slug, e.g. "amex-mr"
 * @param date    - Optional specific date (YYYY-MM-DD)
 * @param enabled - Whether to start the connection (default true)
 */
export function useLiveSearch(
  from: string,
  to: string,
  cabin: string,
  program: string,
  date?: string,
  enabled = true,
) {
  const store = useLiveSearchStore();
  const esRef = useRef<EventSource | null>(null);
  const timerRef = useRef<ReturnType<typeof setInterval> | null>(null);

  useEffect(() => {
    if (!enabled || !from || !to) return;

    // Reset store and start live mode
    store.startLive();

    // Elapsed time timer (updates every 1s)
    const startTime = Date.now();
    timerRef.current = setInterval(() => {
      store.setElapsed(Math.round((Date.now() - startTime) / 1000));
    }, 1000);

    // Build query string
    const params = new URLSearchParams({
      from,
      to,
      class: cabin,
      program,
    });
    if (date) params.set('date', date);

    const es = new EventSource(`/api/flights/live-search?${params.toString()}`);
    esRef.current = es;

    // ── Named event listeners (MUST use addEventListener, NOT onmessage) ──

    es.addEventListener('scraper-started', (e: MessageEvent) => {
      const d = JSON.parse(e.data);
      store.updateScraper(d.scraper, {
        name: d.name,
        status: 'running',
        message: 'Starting...',
      });
    });

    es.addEventListener('scraper-progress', (e: MessageEvent) => {
      const d = JSON.parse(e.data);
      store.updateScraper(d.scraper, {
        status: 'running',
        message: d.message,
      });
    });

    es.addEventListener('result', (e: MessageEvent) => {
      const d = JSON.parse(e.data);
      store.addResult(d.flight as LiveFlightResult);
    });

    es.addEventListener('scraper-done', (e: MessageEvent) => {
      const d = JSON.parse(e.data);
      store.updateScraper(d.scraper, {
        status: 'done',
        message: `${d.resultCount} found`,
        resultCount: d.resultCount,
      });
    });

    es.addEventListener('scraper-error', (e: MessageEvent) => {
      const d = JSON.parse(e.data);
      store.updateScraper(d.scraper, {
        status: 'error',
        message: d.error || 'Unknown error',
      });
    });

    es.addEventListener('scraper-skipped', (e: MessageEvent) => {
      const d = JSON.parse(e.data);
      store.updateScraper(d.scraper, {
        status: 'skipped',
        message: d.reason || 'Skipped',
      });
    });

    es.addEventListener('complete', () => {
      store.finishLive();
      if (timerRef.current) clearInterval(timerRef.current);
    });

    es.addEventListener('search-error', (e: MessageEvent) => {
      const d = JSON.parse(e.data);
      // Store the error as a scraper entry so the UI can display it
      store.updateScraper('__search-error', {
        name: 'Search',
        status: 'error',
        message: d.message || 'Live search failed',
      });
      store.finishLive();
      if (timerRef.current) clearInterval(timerRef.current);
    });

    // Fallback error handler: detect connection death
    es.onerror = () => {
      if (es.readyState === EventSource.CLOSED) {
        store.finishLive();
        if (timerRef.current) clearInterval(timerRef.current);
      }
      // If readyState is CONNECTING, EventSource is auto-reconnecting — let it retry
    };

    // ── Cleanup ──
    return () => {
      es.close();
      esRef.current = null;
      if (timerRef.current) {
        clearInterval(timerRef.current);
        timerRef.current = null;
      }
      store.resetLive();
    };
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [from, to, cabin, program, date, enabled]);
}
```

**Key design decisions:**

1. **`store` is accessed via `useLiveSearchStore()` at hook top level.** The store reference is stable (Zustand returns the same object across renders). The actions (`startLive`, `addResult`, etc.) are stable references since they are defined in `create()`. This is safe to call in the effect without adding every action to the dependency array.

2. **`URLSearchParams` for query string building.** Handles encoding automatically. The `class` parameter is used (not `cabin`) because that is what Harbor's Express endpoint expects (`req.query.class`).

3. **`eslint-disable-next-line react-hooks/exhaustive-deps`**: The `store` object is stable and does not need to be in the dependency array. Adding it would cause infinite re-renders since each `set()` call creates a new state slice (though the store ref itself is stable). The `enabled` param is included so that toggling `enabled` properly opens/closes the connection.

4. **`search-error` stored as a pseudo-scraper entry** (`__search-error`): This allows the `LiveSearchProgress` component (Plan 05-03) to display the error message using the same scraper status rendering logic, without a special case.

5. **No `AbortController`**: The `EventSource` API does not support abort signals. Cleanup is done by calling `es.close()` in the effect return function, which causes Harbor's `req.on('close', ...)` handler to fire and abort the server-side scrape.

6. **When `readyState === CONNECTING` on error**: EventSource auto-reconnects per the spec. We only call `finishLive()` when `readyState === CLOSED` (permanent failure). This provides built-in resilience for transient network issues.
